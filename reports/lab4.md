# Lab4：文件状态与硬链接

## 实现概述

实现 fstat、linkat 和 unlinkat。目录项保存名字到 inode 的对应关系，多个名字共享同一个 inode。通过根目录扫描计算链接数；删除目录项后复用空槽。最后一个名字和最后一个打开描述都消失时才释放文件数据、间接块和 inode 位图，保留打开后 unlink 的语义。

## 修改与思路

- `easy-fs/src/efs.rs`：增加仅内存中的打开描述计数，并提供磁盘 inode 位置到 inode 编号的逆变换，磁盘格式保持兼容镜像构建器。
- `easy-fs/src/vfs.rs`：增加 link/unlink/stat/open/close，复用删除后的目录空槽，查询与 ls 跳过空项；创建时校验文件名长度和扁平目录限制。
- `os/src/fs/mod.rs`：File trait 提供默认不支持的 stat；Stat 构造器初始化填充区，避免暴露未初始化字节。
- `os/src/fs/inode.rs`：OSInode 统计打开描述，Drop 执行 close；返回 inode 编号、类型与实时链接数；暴露 link_file/unlink_file。
- `os/src/syscall/fs.rs`：补齐三个系统调用，检查描述符，并通过用户页表逐页写入 Stat。
- `syscall/process.rs`、`task`、`mm`：迁移前章时间、映射、spawn 与 stride，spawn 从文件系统读取 ELF；exec 同步重置堆边界。

## 问答

### 文件描述符和打开文件

描述符是某个进程表中的整数下标；表项引用打开文件描述，其中包含访问权限和偏移。两次 open 同一 inode 得到独立偏移；fork 克隆 Arc 后父子共享同一个打开描述，因而也共享偏移。硬链接共享 inode 和内容，不要求共享打开偏移。

### 硬链接与符号链接

硬链接是另一个名字直接指向同一 inode，删除一个名字不删除其他名字，内容修改对所有名字可见。符号链接是存储目标路径的另一种文件，目标被删除后可以成为悬空链接。本实验只实现硬链接；扁平 easy-fs 不支持跨文件系统和目录硬链接。

### 删除与回收

unlink 先删除名字，nlink 下降；文件仍被打开时，已有 fd 应可继续访问。数据生命周期不等于某个名字的生命周期。实现用打开描述计数配合目录扫描，最后 close 时才回收未链接 inode，避免 fd 指向已复用的数据。目录采用空槽而不是移动所有目录项，后续 create/link 优先复用空槽，数据块和 inode 位图会释放。

### root inode 的作用与损坏后果

root inode 是扁平目录的入口，其数据块保存所有文件名到 inode 编号的映射。文件的实际数据和 inode 位图即使还在，根目录项损坏也会使按名字查找失败、指向错误 inode，严重时断言失败或读到错误文件。恢复不能只修复某一个 fd，需要借助备份、目录一致性检查或磁盘扫描重建映射；本教学文件系统没有日志恢复机制。

### 第七章问答：管道的实际用途

例如 `cat notes.txt | wc -l`：shell 建立管道，把 cat 的标准输出接到写端，把 wc 的标准输入接到读端；cat 读文件并写入字节，wc 统计换行符。各进程应关闭未使用的端点，否则读端可能因仍有写端引用而等不到 EOF。

### 第七章问答：多进程通信设计

可设计内核管理的命名消息队列：进程通过名称或句柄找到队列，用 send/receive 交换带长度的消息，内核维护发送者、接收者和容量限制，满队列发送或空队列接收可阻塞。多个进程共用一个队列，消息携带发送者和目标标识，避免为每一对进程建立管道；还需要权限检查、进程退出时的引用回收和超时处理。另一种方案是共享内存加同步原语，但程序需要自行处理竞争与消息边界。
